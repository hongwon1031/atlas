# Atlas 제품 비전

> 출처: [00. Vision & Constitution](https://app.notion.com/p/3cd9f036b307810c97cce841de115a37) (2026-08-31 동기화)

## Mission

한 사람이 휴대전화에서 AI 팀을 운영하여 안전하고 반복 가능한 방식으로 소프트웨어를 개발할 수 있도록 합니다.

## Product Vision

Atlas는 단일 코딩 챗봇이 아닙니다. Atlas는 프로젝트별 컨텍스트, 역할, 권한, 예산, 실행 환경을 관리하고 여러 AI 모델과 코딩 에이전트를 조율하는 **AI Workforce Operating System**입니다.

## 문제 인식

- AI 코딩 세션은 종료되면 중요한 맥락이 사라집니다.
- 여러 모델을 병행하면 작업 중복과 충돌이 발생합니다.
- 사용자는 평일에 PC 앞에 없어서 휴대전화 중심의 지시와 검토가 필요합니다.
- 각 모델의 사용량과 가용성이 다르며 특정 공급자에 종속되기 쉽습니다.
- 자율 작업이 편리할수록 보안, 오작동, 무단 merge 위험이 커집니다.

## 핵심 가치

1. **Context First** — 모델보다 올바른 컨텍스트 선별이 우선입니다.
2. **Project Memory** — 기억은 대화가 아니라 프로젝트 저장소에 남습니다.
3. **Human Approval** — 위험한 변경과 최종 반영은 사람이 승인합니다.
4. **Vendor Neutrality** — Codex, Claude Code, OpenHands 등 실행기를 교체할 수 있어야 합니다.
5. **Observable Work** — 계획, 실행, 로그, 테스트, 비용, 결과를 추적합니다.
6. **Least Privilege** — 역할과 작업에 필요한 최소 권한만 부여합니다.

## 성공 상태

- 휴대전화에서 자연어로 작업을 생성합니다.
- 작업에 맞는 올바른 프로젝트만 선택합니다.
- 관련 컨텍스트를 자동으로 수집합니다.
- 적합한 에이전트에 작업을 배정합니다.
- 격리된 환경에서 구현하고 테스트합니다.
- PR과 요약 보고서를 생성합니다.
- 휴대전화에서 사람이 검토하고 승인합니다.

## 비전 검증 질문

- [ ] Atlas 없이도 쉽게 해결되는 문제를 다시 만들고 있지 않은가?
- [ ] 단일 모델보다 여러 실행기를 조율할 때 명확한 가치가 있는가?
- [ ] PC 없이도 핵심 흐름을 수행할 수 있는가?
- [ ] 회사 프로젝트와 개인 프로젝트를 기술적으로 격리할 수 있는가?
- [ ] 모델이 바뀌어도 프로젝트 기억과 워크플로가 유지되는가?
